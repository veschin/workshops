* Примеры проблем
** Глубокое вложенное состояние
Frontend-приложениям часто нужно обновлять глубоко вложенные данные в состоянии. Это приводит к многословному коду и ошибкам при ручном управлении иммутабельностью [[https://react.dev/learn/updating-objects-in-state][React docs on nested state]].

| Стек          | Решена проблема |
|---------------+-----------------|
| React         | Нет             |
| Vue           | Нет             |
| ClojureScript | Да              |

В ClojureScript проблема решена благодаря иммутабельным структурам данных и функции assoc-in, которая позволяет декларативно обновлять вложенные значения без ручного копирования объектов.

Ссылка на примеры: [[file:01-nested-state/][Код]]

| Стек          | Решена проблема |
|---------------+-----------------|
| React         | Нет             |
| Vue           | Нет             |
| ClojureScript | Да              |

В ClojureScript проблема решена благодаря реактивным атомам и функции add-watch, которая автоматически отслеживает изменения состояния без необходимости управлять зависимостями вручную.

Ссылка на примеры: [[file:02-useeffect-hell/][Код]]
** Реактивные ловушки
Деструктуризация и другие операции могут случайно сломать реактивность, приводя к несогласованным состояниям UI [[https://vuejs.org/guide/essentials/reactivity-fundamentals.html][Vue reactivity fundamentals]].

| Стек          | Решена проблема |
|---------------+-----------------|
| React         | Нет             |
| Vue           | Нет             |
| ClojureScript | Да              |

В ClojureScript проблема решена благодаря строгой иммутабельности - все изменения состояния создают новые структуры данных, гарантируя согласованность и отсутствие побочных эффектов от деструктуризации.

Ссылка на примеры: [[file:03-reactivity-footguns/][Код]]

| Стек          | Решена проблема |
|---------------+-----------------|
| React         | Нет             |
| Vue           | Нет             |
| ClojureScript | Да              |

В ClojureScript проблема решена благодаря структурному разделению данных - система автоматически определяет, какие части UI нужно обновить, без необходимости ручных оптимизаций типа memo или useCallback.
