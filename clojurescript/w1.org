** История создания ClojureScript
ClojureScript был создан Ричем Хики в 2011 году как компиляция Clojure в JavaScript.
Знаменитая фраза создателя объясняет мотивацию:
#+begin_quote
Clojure rocks, JavaScript reaches
#+end_quote

[[https://clojurescript.org/about][ClojureScript: About]].
JavaScript доминировал в вебе, но страдал от проблем с инструментами, динамической типизацией и сложностью поддержки крупных приложений. ClojureScript предложил решение: мощный функциональный Lisp с возможностями продвинутой компиляции через Google Closure Compiler.

** Позиционирование в экосистеме
ClojureScript занимает уникальную нишу среди языков, компилируемых в JavaScript:
- В отличие от TypeScript фокусируется на функциональной парадигме, а не на типах
- В отличие от Elm предлагает более зрелую экосистему и промышленное применение
- Сохраняет Lisp традиции homoiconicity и REPL-разработки

* Фундаментальные концепции
** Миф о скобках: ClojureScript против TypeScript
Сравним два подхода к решению одной задачи — параллельная загрузка API с логированием:

#+begin_src clojure
(defn fetch-apis []
  (-> (js/Promise.all [(let [log-json [url label]
                             (-> (js/fetch url)
                                 (.then #(.json %))
                                 (.then #(js/console.log (str label ":") %))
                                 (.catch #(js/console.error (str label " error:") %)))]
                        (log-json "/api/users" "Users")
                        (log-json "/api/posts" "Posts")
                        (log-json "/api/comments" "Comments")))]
      (.catch #(js/console.error "Общая ошибка API:" %))))
#+end_src

#+begin_src typescript
async function fetchApisOptimized() {
  const logJson = async (url: string, label: string) => {
    try {
      const response = await fetch(url);
      const data = await response.json();
      console.log(*${label}:*, data);
    } catch (error) {
      console.error(*${label} error:*, error);
    }
  };

  await Promise.all([
    logJson('/api/users', 'Users'),
    logJson('/api/posts', 'Posts'),
    logJson('/api/comments', 'Comments')
  ]);
}
#+end_src

Количество синтаксических элементов:
| Тип скобок    | ClojureScript | TypeScript |
|---------------+---------------+------------|
| Круглые ()    |            20 |         14 |
| Квадратные [] |             1 |          1 |
| Фигурные {}   |             0 |          2 |
| Итого пар     |            21 |         17 |

** Homoiconicity: Код как данные
ClojureScript наследует из Lisp принцип homoiconicity — код имеет ту же структуру, что и данные. Это стирает границу между программированием и обработкой данных.
*** Базовые структуры данных
Четыре основные коллекции в ClojureScript:

| Структура   | Описание                      | Аналог в JavaScript      |
|-------------+-------------------------------+--------------------------|
| Vector *[]* | Упорядоченный список          | Array                    |
| Map *{}*    | Ассоциативный массив          | Object или Map           |
| List *()*   | Последовательность            | LinkedList (нет нативно) |
| Set *#{}*   | Множество уникальных значений | Set                      |

#+begin_src clojure
;; Коллекции в ClojureScript
(def data [1 2 3])           ; vector
(def obj {:name "John" :age 30})  ; map
(def items #{:a :b :c})      ; set

;; Доступ к данным через keywords как функции
(:name obj)  ; => "John"
#+end_src

*** Код как данные
В ClojureScript можно манипулировать кодом как обычными данными:

#+begin_src clojure
;; Код как данные
(def code '(+ 1 2))         ; list без выполнения
(eval code)                ; => 3

;; Манипуляция кодом
(conj code 3)               ; => (+ 1 2 3)
(eval (conj code 3))        ; => 6
#+end_src

- Тестировать UI в REPL

** Неизменяемость и структурное разделение
Все коллекции в ClojureScript неизменяемые по умолчанию. Операции создают новые версии через structural sharing:

#+begin_src clojure
(def data {:count 0})
(def updated (assoc data :count 1))  ; новая версия

data       ; => {:count 0}  (не изменился)
updated    ; => {:count 1}
#+end_src

** Преимущества для фронтенда
- Простота обновления вложенного состояния через *get-in/assoc-in*
- Предсказуемая производительность через сравнение по ссылке
- Естественная работа с данными без дополнительного состояния
* Синтаксический сахар и возможности языка
** Деструктуризация
ClojureScript поддерживает мощную деструктуризацию для удобной работы со структурами данных.

*** Базовая деструктуризация
#+begin_src clojure
(let [{:keys [name age]} user]
  (str name " возраст " age))
#+end_src

*** Вложенная деструктуризация
#+begin_src clojure
(let [{{:keys [street city]} :address} user]
  (str street ", " city))
#+end_src

*** Значения по умолчанию
#+begin_src clojure
(let [{:keys [name age]
       :or {age 18}} user]
  (str name " возраст " age))
#+end_src

** Threading macros
Трединг макросы преобразуют вложенные вызовы в линейные потоки данных.

*** Thread-first (->)
Подставляет результат как первый аргумент:
#+begin_src clojure
(-> user
    :profile
    :settings
    :theme)
#+end_src

*** Thread-last (->>)
Подставляет результат как последний аргумент:
#+begin_src clojure
(->> users
     (filter :active)
     (map :name)
     (take 5))
#+end_src

*** Безопасная навигация (some->)
Не выполняется если промежуточный результат nil:
#+begin_src clojure
(some-> user
        :address
        :city
        str/upper-case)
#+end_src

* REPL-Driven Development
** История и философия REPL
REPL (Read-Eval-Print Loop) происходит из традиций Lisp, созданных Джоном Маккарти в 1958 году [[https://en.wikipedia.org/wiki/REPL][REPL: Wikipedia]].

Эта концепция интерактивной разработки стала отличительной чертой всех Lisp-диалектов. Clojure продолжил эту традицию с nREPL (сетевой REPL) в 2007 году [[https://nrepl.org/][nREPL: a networked REPL for Clojure]], а ClojureScript адаптировал REPL для браузерной среды, позволяя интерактивно работать с DOM и состоянием приложения в реальном времени [[https://clojurescript.org/reference/repl][ClojureScript REPL]].

** Как работает REPL в ClojureScript
Основной цикл REPL:
1. *Read* — чтение и парсинг выражения
2. *Eval* — выполнение кода с сохранением состояния
3. *Print* — вывод результата
4. *Loop* — возврат к началу для следующей команды

В отличие от JavaScript консоли браузера, REPL позволяет:
- Сохранять определения между выполнениями
- Работать с пространствами имён
- Использовать полноценные отладочные инструменты

** Практический workflow
1. Запустить REPL сервер
2. Подключиться к нему из редактора
3. Написать функцию и выполнить её немедленно
4. Протестировать с реальными данными
5. Итерировать без перезагрузки браузера

** Отладка с tap>
tap> отправляет данные в REPL для потоковой отладки без лишних console.log:
#+begin_src clojure
(defn process [data]
  (tap> {:input data})
  (let [result (transform data)]
    (tap> {:output result})
    result))
#+end_src

** Преимущества подхода
- Мгновенная обратная связь без пересборки
- Сохранение состояния между изменениями кода
- Возможность исследования данных в реальном времени
- Естественная среда для прототипирования
* Интероп с JavaScript
** Использование npm пакетов
ClojureScript может напрямую использовать любые npm пакеты:

#+begin_src clojure
(:require ["@mui/material" :refer [Button TextField]])

(defn form []
  [:div
   [:> TextField {:label "Имя"
                  :value @name
                  :on-change #(reset! name (.. % -target -value))}]
   [:> Button {:variant "contained"
               :on-click submit}
    "Отправить"]])
#+end_src

** Паттерн обёртки (wrapper)
Для удобного использования JS библиотек создаются обёртки:

#+begin_src clojure
(defn mui-button [props & children]
  (into [:> Button (clj->js props)] children))

;; Использование обёртки
[mui-button {:variant "contained"
             :on-click handle-click}
 "Нажми меня"]
#+end_src

** Конвертация данных
Для работы между ClojureScript и JavaScript используются функции конвертации:

- *clj->js* — преобразует ClojureScript структуры в JavaScript
- *js->clj* — преобразует JavaScript объекты в ClojureScript структуры

** Интеграция с npm
Все современные npm пакеты работают в ClojureScript:
- Импорт через синтаксис *:require*
- Автоматическая обработка зависимостей
- Поддержка tree-shaking и оптимизации

* Сборщики проектов
** shadow-cljs
Создан Томасом Хеллером в 2017 году, стал стандартом для современной ClojureScript разработки [[https://shadow-cljs.github.io/docs/UsersGuide.html][shadow-cljs: User's Guide]].
*** Возможности
- Простая настройка проектов
- Бесшовная интеграция с npm экосистемой
- Быстрые инкрементальные сборки
- Надёжное кэширование
- Поддержка ES модулей

*** Преимущества
- Минимальная конфигурация
- Автоматическая обработка зависимостей
- Интеграция с современными JavaScript инструментами
** figwheel-main
Развитие оригинального Figwheel Брюса Хаумана, начатого в 2014 года [[https://figwheel.org/][Figwheel: Live reloading for ClojureScript]].
*** Особенности
- Пионер live reloading в ClojureScript
- Автоматическая перезагрузка кода в браузере
- Сохранение состояния приложения между перезагрузками
- Интеграция с REPL
*** Сравнение с shadow-cljs
figwheel делает акцент на разработке, shadow-cljs — на простоте настройки и npm интеграции.
** Google Closure Compiler
ClojureScript использует Google Closure Compiler для оптимизации кода [[https://developers.google.com/closure/compiler][Google Closure Compiler: Documentation]].
*** Advanced compilation
- Агрессивная минификация кода
- Удаление неиспользуемого кода (dead code elimination)
- Переименование переменных и функций
- Оптимизация вызовов функций
*** Преимущества
- Создаёт очень компактные бандлы
- Высокая производительность
- Совместимость с современными браузерами
