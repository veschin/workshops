* Инструментарий
** IDE для вайбкода
- SST/OpenCode `npx -y opencode-ai@latest`
- Claude CLI `npx -y @anthropic-ai/claude-code`
  
Основные возможности:
- Доступ LLM к файлам
- LLM Агенты
- Интеграция с MCP инструментами
- Многомодальные возможности (картинки, аудио, видео)

** Вендоры
*** OpenRouter
Агрегатор моделей от разных провайдеров. Один API — много моделей.

Особенности:
- Доступ к GPT, Claude, Llama, Mistral и другим
- Единый формат запросов
- Ротация провайдеров при падениях
  
*** Claude
Модели от Anthropic по подписке:
- Sonnet
- Opus
- Haiku

*** z.ai
Модели от z.ai по подписке:
- GLM4.6
- GLM4.6V
- GLM4.7

** MCP
Model Context Protocol — протокол для обмена данными между AI агентами и внешними инструментами.

Готовые MCP серверы:
- Файловой системы
- Git репозиториев
- Поиска в коде
- Баз данных
- HTTP запросов

Конфигурация для OpenCode:

#+begin_src json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/path/to/dir"]
    }
  }
}
#+end_src

** OpenSpec
Фреймворк от Fission AI для создания спецификаций и следования им при работе с LLM.

Пример спецификации:

#+begin_src yaml
name: UserSchema

    type: integer
  name:
    type: string
  email:
    type: string
    format: email

#+end_src

*** Thinking
Режим, при котором модель показывает рассуждения перед ответом.

Применяется в Claude и некоторых open source моделях.

Плюсы:
- Виден ход мыслей
- Лучше на сложных задачах

Минусы:
- Дольше ответ
- Дороже токены

*** Промпты
Текстовый запрос к модели.

Типы:
- System prompt — глобальные инструкции
- User prompt — запрос пользователя
- Assistant prompt — предыдущие ответы модели

*** Prompt Engineering
Методы формирования эффективных промптов.

Принципы:
- Чёткая задача
- Контекст входных данных
- Желаемый формат вывода
- Примеры при необходимости

*** System prompt vs User prompt
System prompt задаёт глобальное поведение модели.

Пример:
#+begin_src
Ты — Senior инженер по программному обеспечению.
Отвечай кратко.
Код — на Rust.
#+end_src

System prompt применяется один раз, user prompt — на каждое сообщение.

*** Chain of Thought
Метод, при котором модель просят показать ход рассуждений.

Пример промпта:
#+begin_src
Реши задачу пошагово.
Покажи каждый этап.
В конце — итоговый ответ.
#+end_src

Помогает на сложных задачах, увеличивает расход токенов.

*** Few-shot prompting
Демонстрация примеров для формата и стиля ответа.

Пример:
#+begin_src
Переведи с английского на русский:

Input: Hello World
Output: Привет мир

Input: Machine Learning
Output: Машинное обучение

Input: Artificial Intelligence
Output:
#+end_src

*** Function calling
Возможность вызова внешних функций через модель.

Модель не выполняет код — возвращает JSON с аргументами для вызова функции.

Пример конфигурации для OpenCode:

#+begin_src json
{
  "tools": [{
    "name": "weather",
    "description": "Получить погоду",
    "parameters": {
      "type": "object",
      "properties": {
        "city": {"type": "string"}
      },
      "required": ["city"]
    }
  }]
}
#+end_src

*** Fine-tuning
Адаптация модели на собственных данных.

Применяется когда:
- Нужен специфический стиль
- Узкая доменная область
- Промпты не дают нужного качества

Требует:
- Данных (минимум 100 примеров)
- Вычислительных ресурсов
- Времени на обучение

Для большинства задач достаточно prompt engineering и function calling.

* База
** Нейронка и нейросеть
Нейронка — математическая модель, имитирующая работу биологического нейрона.

Нейросеть — несколько нейронов, соединённых в слои.

Элемент нейронки:
- Входы (числа)
- Веса (коэффициенты)
- Выход (число)

Обучение — подбор весов так, чтобы выход соответствовал ожидаемому.

** LLM — Large Language Model
LLM — нейросеть, обученная на текстах.

Отличие от обычной нейросети:
- Размер модели (миллиарды параметров)
- Тип данных (текст)
- Архитектура (Transformer)
- Задача (предсказание следующего токена)

** Обычная нейросеть против LLM
Обычная нейросеть:
- Маленькая или средняя
- Решает одну задачу (классификация, регрессия)
- Фиксированный вход/выход
- Обучается на специфических данных

LLM:
- Большая
- Универсальная (код, текст, анализ, генерация)
- Переменный вход/выход
- Обучается на всей доступной текстовой информации

** Почему LLM называют "большим языковым"
Работает с естественным языком и кодом.

"Большим" — количество параметров:
- GPT-3: 175 млрд
- Claude 3: несколько сотен миллиардов
- Llama 3 70B: 70 млрд

Количество параметров не равно качеству напрямую. Архитектура и данные важнее.

* Как работает LLM
** Слот машина
LLM предсказывает следующий токен.

Общение с LLM — это взаимодействие со случайным генератором. На вход подаётся запрос, на выход получается результат, который определяется распределением вероятностей.

На вход: последовательность токенов.
На выход: распределение вероятностей следующего токена.

Пример:
- Вход: "Hello"
- Выход (вероятности): World (0.4), there (0.3), I (0.2), ...

Модель не "решает". Она выдаёт вероятности. Результат случаен, параметр температуры влияет на выбор менее вероятных токенов, что ведёт к большей креативности или предсказуемости.

Повторяется: новый токен добавляется к входу, снова предсказывается следующий.

** Токены
Минимальная единица текста для LLM.

Один токен ≈ 4 символа английского текста или 0.75 слова.

Примеры:
- "Hello" → "Hello" (1 токен)
- "Hello world" → "Hello" (1), " world" (1)
- "привет мир" → "при" (1), "вет" (1), " мир" (1)

Чем больше токенов — тем дороже.

** Контекстное окно
Максимальное количество токенов, которое модель может обработать за раз.

Типичные значения:
- GPT-3.5: 4K
- GPT-4o: 128K
- Claude 3.5: 200K
- Llama 3.1 70B: 128K

Контекст включает:
- Системный промпт
- Историю диалога
- Входные данные
- Выход модели

Если контекст переполнен — старые токены обрезаются.

** Attention mechanism
Механизм, который позволяет модели фокусироваться на разных частях входа.

При генерации токена модель учитывает все предыдущие токены с разным весом.

Пример:
- Текст: "Яблоко — это фрукт"
- При генерации "фрукт" модель больше внимания уделяет слову "Яблоко"

Attention позволяет учитывать контекст на большом расстоянии.

* Почему LLM не сможет думать за вас
** У AI нет мнения — только вероятности
LLM не имеет мнения, убеждений или предпочтений.

Каждое слово — результат предсказания вероятности на основе тренировочных данных.

Модель может имитировать мнение, но это паттерн из данных.

** Галлюцинации
Ситуация, когда модель генерирует неправдоподобную, но неверную информацию.

Причины:
- Модель не знает факт
- Недостаточно информации в контексте
- Высокая temperature

Модель не отличает правду от лжи — генерирует текст, который выглядит правдоподобно.

** AI не понимает — продолжение паттернов
LLM не понимает текст так как понимает человек.

Для модели — это последовательность чисел, которую нужно продолжить.

Модель не имеет:
- Семантического понимания
- Модели мира
- Здравого смысла

** AI не может валидировать то, что написал
LLM не проверяет правильность своего вывода.

Модель может написать код, который выглядит работающим, но:
- Использует несуществующие библиотеки
- Содержит логические ошибки

Валидация — отдельная задача, LLM не гарантирует результат.

** Вам всё равно придется думать
LLM — инструмент, не заместитель.

Результат требует:
- Понимания задачи
- Валидации выхода
- Рефакторинга
- Интеграции в проект

LLM ускоряет работу.
